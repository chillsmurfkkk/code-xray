# «Структура»: приймання знімків і перегляд коду

Оновлено 2026-10-26. Сторінка показує готовий `ParsedSnapshot`: файли, типи й
функції в дереві, весь текст вибраного файла та позначення діапазону сутності.

## Контракт для координатора

`StructurePage::setSnapshot(std::shared_ptr<const xray::code::ParsedSnapshot>,
bool demonstration = false)` викликається в GUI-потоці. Сторінка утримує
знімок і його джерела, поки вони відображаються. Передавання `nullptr`
повертає стан «джерело не відкрито» та прибирає дерево, текст, шлях і позначення.

Метод приймає завершений результат; збирання файлів, розбір, прогрес,
скасування та відсіювання застарілих задач залишаються відповідальністю
координатора C. Доменні API та їхні типи в цій зміні не змінювались.

Новий знімок перебудовує дерево під `QSignalBlocker` й очищає попередній код.
Кожен елемент зберігає індекс `ParsedUnit` та перший/останній рядки сутності.
Рекурсія проходить `CodeEntity::children`, підпис бере з `describe()`.
Часткове покриття знімка, джерела або окремої одиниці позначається в контексті.

`currentItemChanged` обслуговує мишу й клавіатуру. Вибір файла відкриває весь
його текст без вигаданого діапазону; вибір функції або типу переходить до початку
сутності й позначає її рядки. Текст береться з `FileEntity::sourceBytes`;
повторного читання диска чи запуску парсера у віджетах немає.

Шлях доступний у read-only полі заголовка й підказці: його можна виділити та
скопіювати, а довге ім'я не розтягує панель. Код також доступний лише для читання.
Стан без джерела, успішний порожній результат, порожній файл та відсутній текст
вибраного файла розрізняються.

## Рядки й оформлення

Для показу UTF-8 декодується в QString, початковий BOM прибирається, CRLF
нормалізується в LF; оригінальні байти в знімку залишаються незмінними.
Таблиця позицій зіставляє початки початкових LF-рядків із UTF-16 позиціями Qt.
Це враховує emoji та Unicode-роздільники абзаців, які Qt може відображати
додатковими блоками. Байтові offsets напряму в QTextCursor не передаються.

ExtraSelection задає лише фон рядків сутності, не змінюючи текст або робоче
виділення користувача. Кінцевий рядок також позначається на всю ширину, зокрема
коли функція завершується в EOF. При зміні палітри чи стилю позначення
перебудовується без повторного завантаження тексту. Некоректний діапазон
не створює позначення й не приховує доступний файл.

Власний делегат малює заокруглений вибір елемента дерева, залишаючи гілки й
відступи прозорими. Клавіатурний фокус віджета має окрему рамку.

## Демонстрація

```powershell
cmake --build --preset windows-x64 --target code-xray
& ./build/windows-x64/Debug/code-xray.exe --demo
```

`--demo` передає ручну фікстуру з `demo/example.cpp` та `square` і явно
позначає її демонстраційними даними. Звичайний запуск починається без джерела.

## Перевірка

Windows x64, MSVC v143, Qt 6.11.1 Debug. Збірка `gui_snapshot_tests` і
`gui_design_tests` пройшла. Повний `ctest --preset windows-x64 --output-on-failure`
пройшов **16/16**; у sandbox TEMP/TMP спрямовано в `build/gui-snapshots/temp`.

`gui_snapshot` записує тимчасові C++ файли та виконує справжні `collect()` і
`parse()` через `std::async` у worker-потоці. Потім передає результат сторінці
в GUI-потоці й перевіряє:

- весь текст знімка після зміни початкового файла на диску;
- вибір правильного файла для однойменних функцій, перехід і прокручування;
- BOM, CRLF, кирилицю, emoji, U+2028 та U+2029 у джерелі;
- діапазон, його очищення й оновлення кольору без втрати виділеного користувачем тексту;
- прозорість відступів дерева при виборі функції;
- частковий результат, відсутні байти, некоректні межі й різні порожні стани;
- утримання знімка після звільнення його викликачем та звільнення після очищення;
- явне позначення демонстраційної фікстури.

Окремий `gui_demo_startup` перевіряє запуск `--demo --smoke-test`.

Переглянуті рендери реальних віджетів через `QWidget::grab()`:
[темна тема](screenshots/gui-snapshot-dark.png),
[світла тема](screenshots/gui-snapshot-light.png).
Тести використовують `WA_DontShowOnScreen`; сторонні вікна до зображень не входять.

Перевірка на macOS у цій сесії не виконувалась. Вибір папки через GUI, фоновий
координатор, пошук/фільтри, номери рядків і підсвічування синтаксису залишаються
наступними етапами. Цей результат не означає завершення чотирьох форм ЛР №2.
