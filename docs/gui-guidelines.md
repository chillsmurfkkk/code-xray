# GUI: спільне оформлення та еталонна сторінка

Цей документ фіксує погоджений напрям дизайну Code Xray. Еталон для реалізації —
сторінка «Код → Структура». Каркас уже має навігацію, обидві теми й порожні
стани сторінки. Приймання знімків, навігація по коду, вибір папки, фоновий
запуск зі скасуванням, пошук і фільтри, номери рядків та підсвічування синтаксису
реалізовані. Сторінка [«Джерело»](gui-source.md) підтримує папку, явний список
файлів, прогрес етапів і скасування. Сторінка «Діагностика» показує
повідомлення збору й розбору; повний координатор C ще розробляється.

Оформлення уточнено 2026-10-26 за референсами користувача: навігація має спільну
непрозору поверхню, вибір позначається м'якою підкладкою, а тонка акцентна рамка
відведена клавіатурному фокусу. Градієнт поверхонь ледь помітний, без blur,
прозорості, важких тіней і залежності від нативних ефектів Windows чи macOS.

## Погоджені рішення

| Частина | Рішення |
|---|---|
| Палітра | Gruvbox у темній і світлій темах. |
| Тема | При першому запуску темна; перемикання вручну, вибір зберігається між запусками. |
| Характер | М'які форми й композиція, натхненні Apple Liquid Glass, з непрозорими поверхнями без скла, розмиття та важких тіней. |
| Щільність | Помірна: достатньо місця між діями, без великих декоративних карток. |
| Основна навігація | Вузька панель іконок зліва; назва розділу з'являється в підказці при наведенні. |
| Навігація розділу | Поруч з іконками — згортана панель зі списком сторінок поточного розділу. |
| Робочі області | Окремі заокруглені панелі з невеликими проміжками й делікатною різницею фону. |
| Основний акцент | Аквамариновий Gruvbox; відтінок залежить від теми. |
| Шрифти | Системний для інтерфейсу; системний моноширинний для коду. |
| Еталон | «Структура»: дерево зліва, код справа, межу між ними можна перетягувати. |
| Вибрана функція | Показується весь файл із переходом до функції та підсвічуванням її діапазону. |

## Композиція вікна

Зліва направо: панель іконок → список сторінок розділу → робоча область.
Розділи: «Код», «Аналіз», «Історія», «Порівняння». У розділі «Код» сторінки:
«Джерело», «Відбір файлів», «Структура», «Діагностика».

Активний розділ має заокруглену підкладку та акцентний маркер або іконку.
Наведення підсвічує слабше, ніж активний стан. Підказка з назвою доступна також
при клавіатурному фокусі; кожна кнопка-іконка має доступне текстове ім'я.
Перемикач теми розміщується внизу панелі іконок.

Панель іконок і список сторінок об'єднані одним заокругленим контуром із тонким
внутрішнім роздільником. Список сторінок можна згорнути й відкрити знову видимою кнопкою. Згортання
зберігає поточну сторінку, вибір у дереві та позицію коду. Це особливо важливо
на вузькому вікні: навігація не повинна витісняти робочу область.

## Кольори

Вихідні значення взяті з [оригінальної палітри Gruvbox](https://github.com/morhetz/gruvbox/blob/master/colors/gruvbox.vim).
Нижче — початкове призначення кольорів семантичним ролям для еталона.
Компоненти використовують ролі теми, а не власні HEX-значення.

| Роль | Темна | Світла |
|---|---|---|
| Фон вікна | `#282828` | `#fbf1c7` |
| Поверхня панелі | `#32302f` | `#f9f5d7` |
| Наведення / нейтральна підкладка вибору | `#3c3836` | `#ebdbb2` |
| Делікатний роздільник | `#504945` | `#d5c4a1` |
| Основний текст | `#ebdbb2` | `#3c3836` |
| Другорядний текст | `#bdae93` | `#665c54` |
| Акцент / фокус | `#8ec07c` | `#427b58` |
| Текст на суцільній акцентній кнопці | `#282828` | `#fbf1c7` |
| Успіх | `#b8bb26` | `#79740e` |
| Попередження | `#fabd2f` | `#b57614` |
| Помилка | `#fb4934` | `#9d0006` |

Кольори синтаксису централізовані в `SyntaxColors` і `syntaxColors(QPalette)`
у `src/ui/shared/theme.hpp` та `theme.cpp`. Коментарі використовують роль
`PlaceholderText`, директиви — `Accent`; інші категорії мають такі пари Gruvbox:

| Роль у коді | Темна | Світла |
|---|---|---|
| Ключове слово | `#fb4934` | `#9d0006` |
| Числовий токен | `#d3869b` | `#8f3f71` |
| Рядок, символьний літерал або ім'я заголовка | `#b8bb26` | `#79740e` |

Підсвічування задає лише колір символів. Фон діапазону сутності та звичайне
виділення користувача залишаються окремими шарами оформлення.

В оригінальному Gruvbox колір `aqua` має зелений відтінок; саме ця пара
використовується як початковий акцент. Остаточне візуальне сприйняття перевіряємо
на еталонній сторінці в обох темах.

Акцент позначає основну дію, поточний розділ і фокус. Статуси завжди мають
текст або іконку: сам колір не пояснює помилку чи успіх. Для суцільної акцентної
кнопки використовується окрема роль тексту; для виділеного рядка — звичайний
читабельний текст на нейтральній підкладці з акцентним маркером.

## Початкові розміри й типографіка

Ці розміри — робочі значення для першої реалізації, а не окремо погоджені
дизайнерські вимоги. Їх можна уточнити після перегляду еталона. Усі значення
задаються в логічних одиницях Qt, з урахуванням системного масштабування.

| Елемент | Початкове значення |
|---|---|
| Шкала відступів | 4, 8, 12, 16, 24. |
| Проміжок між робочими панелями | 12. |
| Внутрішній відступ панелі | 16. |
| Радіус панелі / кнопки-іконки / поля | 16 / 12 / 8. |
| Панель іконок / список сторінок | Близько 64 / 210 завширшки, зі збільшенням під системний шрифт. |
| Кнопка-іконка / сама іконка | 40 × 40 / близько 20. |
| Поле або звичайна кнопка | Від 32 заввишки, зі збільшенням під системний шрифт. |
| Рядок дерева | Від 28 заввишки, без обрізання тексту. |
| Дерево / код | Початково близько 30% / 70% робочої ширини. |

Інтерфейс використовує системний шрифт QApplication, заголовки відрізняються
розміром або вагою. Для коду використовуємо системний fixed-width шрифт.
Не прив'язуємо компонування до наявності конкретного шрифту Windows чи macOS.
Довгі шляхи можна скорочувати у заголовку, але повний шлях доступний у підказці
та для копіювання. Поля й кнопки розміщуються через layouts, без фіксованих координат.

## Еталон «Структура»

Сторінка містить заголовок «Структура», короткий контекст відкритого джерела
та дві робочі панелі. Ліва панель має пошук за назвою, фільтр виду сутності,
дію розгортання й дерево «файл → тип / функція». Права показує шлях вибраного
файла та його код. Горизонтальний splitter дозволяє змінити пропорції.

1. **Вибір сутності.** Натискання на функцію відкриває весь файл, прокручує
   до початку функції та делікатно позначає її діапазон. Виділення не перекриває
   підсвічування синтаксису. Вибір файла відкриває його текст без вигаданого
   діапазону функції.
2. **Перегляд коду.** Код доступний лише для читання, з номерами рядків,
   підсвічуванням синтаксису Gruvbox і копіюванням. Відображаються байти знімка,
   що належить результату розбору; зміна файла на диску не підміняє цей текст.
3. **Пошук і фільтри.** Зміна пошуку або виду сутності оновлює дерево без повторного
   запуску парсера. Порожня вибірка пояснює, що збігів немає, і пропонує скинути
   фільтр. Вона відрізняється від відсутності відкритого джерела.
4. **Стани.** До відкриття джерела показується пояснення й дія відкриття.
   Під час роботи видно прогрес і скасування. Частковий розбір має попередження
   та перехід до «Діагностики»; помилка й скасування не виглядають як успішний
   порожній результат. Застаріла задача не підміняє результат нового запуску.

Налаштування теми змінює навігацію, підказки, поля, дерево та код разом,
зберігаючи відкриту сторінку й поточний вибір. Темна тема є початковою незалежно
від теми ОС; подальший вибір користувача зберігається.

## Реалізація та розподіл роботи

Залишається C++20 + Qt 6 Widgets. A відповідає за головне вікно, навігацію
й еталонну сторінку у `src/ui/code/`; C — за координатор і доставку результатів
фонової роботи. B і D реалізують власні сторінки, використовуючи спільне оформлення.
Власні сторінки історії належать C. Межі модулів визначені в [CONTRIBUTING](../CONTRIBUTING.md).

Спільні кольори, налаштування теми й компоненти з'являються в `src/ui/shared/`
разом із першим реальним використанням. A веде їх початкову реалізацію;
зміни, що впливають на всі сторінки, узгоджуються зі споживачами. Сторінки
не копіюють палітру та локальні стилі одна в одної. Не створюємо порожні
сторінки лише заради навігації: неготові пункти явно недоступні з поясненням.

GUI повідомляє про дію користувача й отримує типізований результат через
координатор. Парсер, Git і обчислення не виконуються в обробниках віджетів;
оновлення віджетів відбувається в головному потоці.

Перший еталон можна збирати на контрольному ParsedSnapshot, щоб оформлення
не залежало від готовності Git та всього сценарію аналізу. Демонстраційні дані
позначаються явно. Особистий внесок до лабораторної рахується за фактичними
сторінками й обробниками, без повторного зарахування спільних компонентів.

## Приймання першого еталона

### Поточна реалізація оформлення

- `src/ui/shared/theme.cpp` задає палітру й спільний QSS. Відтінки наведення,
  меж і акцентної підкладки обчислюються з ролей Gruvbox; локальних HEX у сторінках немає.
- `installPopupStyle()` встановлює Fusion через спільний `PopupStyle`.
  Меню й підказки мають маску з радіусом 8, узгоджену з QSS: зовнішні кути
  обрізаються формою вікна. Поверхня меню непрозора; прозорість використовується
  лише поза округлим контуром. Анімації меню й підказок вимкнені, щоб Qt
  не показував прямокутні проміжні знімки. Перевірка — `gui_popup` на Windows.
- `NavigationPanel` об'єднує панель іконок і список сторінок. Сигнал
  `themeToggleRequested()` обробляє `MainWindow`; `setTheme(Theme)` оновлює
  опис перемикача. Згортання приховує список, не створюючи сторінку повторно.
- `makeIcon(Symbol)` використовує власний `QIconEngine` і векторні штрихи Qt,
  що перемальовуються поточною палітрою та масштабуються під DPI. SF Symbols,
  системні набори іконок та нові залежності не потрібні.
- `IconButton` має текстове доступне ім'я й підказку при клавіатурному фокусі.
  Недоступні розділи та сторінки містять пояснення й не виконують фіктивних переходів.
- «Структура» містить дві панелі з заголовками, власний grip для splitter-а й
  явні порожні стани. `setSnapshot(shared_ptr<const ParsedSnapshot>, bool)`
  будує дерево та відкриває байти файла зі знімка. Діапазон сутності позначається
  через ExtraSelection незалежно від звичайного виділення тексту й оновлюється
  разом із темою. Шлях у заголовку можна скопіювати; довгий шлях не розтягує панель.
- «Джерело» відкриває локальну папку або явний список файлів. Тимчасова
  інтеграція `MainWindow` запускає збір і розбір у фоновому потоці,
  показує прогрес етапів і підтримує запит скасування. Повний координатор C
  ще не підключений; [поведінка та перевірки](gui-source.md).
- Відступи гілок дерева залишаються прозорими; делегат малює заокруглений вибір
  лише під вмістом елемента. Миша й клавіатура використовують currentItemChanged.
- `--demo` передає ручний контрольний знімок із явною позначкою демонстрації.
  Інтеграційний тест окремо передає результати справжніх collect/parse;
  [API, перевірки та межі](gui-snapshots.md).
- Компоненти збираються в `xray_ui`. `gui_design` перевіряє тему, її збереження,
  стан навігації, віджети, перенесення тексту й DPI; зображення Qt-рендерингу
  записуються у `build/<preset>/gui-design/`. Межі перевірки — у
  [журналі оформлення](gui-design-verification.md).

### Критерії повного еталона

- Обидві теми застосовуються до всіх компонентів, а ручний вибір зберігається після перезапуску.
- Навігація працює мишею й клавіатурою; підказки та фокус дозволяють зрозуміти кнопки без постійних підписів.
- Список сторінок згортається, splitter змінює ширину дерева й коду, текст не обрізається при масштабуванні.
- Вибір функції показує правильний файл і діапазон знімка; код можна виділити й скопіювати.
- Відсутність джерела, відсутність збігів, частковий результат, помилка, виконання та скасування мають різні повідомлення.
- Вигляд перевірений на Windows x64 і macOS Apple Silicon у темній та світлій темах; фактичні результати й знімки екрана додаються до зміни GUI.
