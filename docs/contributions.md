## Авторство й E0

Власник модуля підтримує його й погоджує зміни. Автор елемента змістовно
його спроєктував/реалізував за наявними доказами. Форматування, використання
типу, перенесення файла й рев'ю самі по собі не передають авторство.

Початкові декларації контрактів додані A в коміті
[`c8ed63c`](https://github.com/chillsmurfkkk/code-xray/commit/c8ed63c).
У B не зараховані поля `AnalysisProfile`, `MetricResult`, `Finding`; у C —
початкові `HistoryRequest`, `CommitRecord`, `ChangeRecord` та спільні типи;
у D — початковий `src/review/types.hpp`. Подальші власні алгоритми роботи
з цими контрактами враховано відповідним авторам. Перелік A обмежений його
модулем `code`, тому початкові контракти решти модулів не збільшують його числа.

Методи одного класу можуть мати різних авторів. Один тип, поле чи алгоритм
не зараховується двом учасникам. `git blame` звіряється з початковим комітом
і diff: переписування відступів може приховати походження незміненого коду.

## Правила обліку

- Кожен підтримує власний `docs/contributions/A.md`–`D.md`; цей файл містить
  підсумок. Код, особисті рядки та підсумок оновлюються разом, якщо зміна
  впливає на лабораторну.
- Для кожного облікованого типу, поля та реалізації є окремий рядок зі сталим
  ID, фактичним символом, посиланням на код і поясненням/доказом. A01–D25
  посилаються на початковий задум; змістовна заміна алгоритму пояснюється.
- Не рахуються aliases, enum, бібліотечний/згенерований код, тестові типи
  та функції, прості getters/setters, конструктори з присвоєннями, чисті
  декларації й обгортки викликів. Конструктор із перевіркою інваріанта може
  бути нетривіальним; такий випадок явно позначений у C.
- Шаблонний алгоритм рахується один раз незалежно від інстанціювань;
  різні клієнти доводять поліморфну поведінку. Успадковане поле рахується
  один раз у класі, що його оголосив.
- Стани: **заплановано**, **реалізовано**, **перевірено**, **продемонстровано**.
  Перевірка має команду, результат і SHA; демонстрація — дату й сценарій.
  Наявність тестового коду сама по собі не доводить його успішного запуску.

Поточний спільний запуск описано в [журналі перевірки](lab1/lab1-verification.md).
Успішна тестова ціль не доводить перевірки всіх гілок кожного алгоритму;
особисті переліки зберігають конкретні зауваження щодо покриття.
